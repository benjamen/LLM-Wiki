# LLM Wiki — template vault

A blank, best-practice **LLM Wiki** (Karpathy pattern) ready for a new topic. Copy this folder,
fill in `purpose.md`, drop sources into `raw/`, and let an agent (Claude Code, pointed at the
vault) compile them into a linked wiki under `wiki/`. You query the wiki, not the raw folder.

This template carries the structure, deterministic tooling, schema, and page templates from a
worked example; all content is empty.

## First steps for a new topic

1. Copy this folder to a new location and (optionally) re-init git — see setup below.
2. **Write `purpose.md`** — what this vault is for (the agent reads it on every ingest/query).
3. **Drop sources into `raw/`** (markdown/txt is easiest; one file per source).
4. **Run an ingest pass:** tell Claude Code *"Read CLAUDE.md and run an ingest pass over raw/."*
5. **Browse in Obsidian** — graph view, `[[wiki-links]]`, and `wiki/indexes/CONCEPT_INDEX.md`.

## Layout

```
raw/            immutable source material (never edited)
wiki/
  summaries/    one summary per source
  concepts/     durable ideas/frameworks
  entities/     people, orgs, tools, systems
  syntheses/    argumentative overviews per cluster
  comparisons/  side-by-side tables
  queries/      substantial filed answers
  indexes/      catalogs (SOURCE_CATALOG, ENTITY_INDEX, CONCEPT_INDEX)
  overview.md   global summary
  catalog.jsonl generated by wiki_tool.py (do not hand-edit)
outputs/        large generated artifacts
schema/         detailed rules   _templates/  page starters
scripts/wiki_tool.py   deterministic maintenance tool
CLAUDE.md       the canonical schema (agents.md points to it)   purpose.md   why this vault exists
```

## Maintenance tooling

Python is required (on Windows it is the **`py` launcher**):

```
py scripts/wiki_tool.py doctor          # health check
py scripts/wiki_tool.py build           # regenerate wiki/catalog.jsonl
py scripts/wiki_tool.py lint            # validate frontmatter, links, sources, orphans
py scripts/wiki_tool.py search "<q>"    # keyword search
py scripts/wiki_tool.py source-status   # which raw/ sources are processed
py scripts/wiki_tool.py log "<msg>" --tag ingest|query|lint|maintain
```

## One-time setup (per copy)

The pre-commit hook (runs `build` + `lint`, blocking commits only on lint **errors**) lives under
`.githooks/`. `core.hooksPath` is a local git setting and is **not** committed, so after copying
and re-initialising git, run once:

```
git config core.hooksPath .githooks
```

`py scripts/wiki_tool.py doctor` reports whether it's set. Bypass for a single commit with
`git commit --no-verify`.

See `CLAUDE.md` and `schema/` for the exact rules the agent follows.
